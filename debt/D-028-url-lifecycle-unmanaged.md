# D-028 — Published URLs derive from filenames, and nothing manages them

> **Summary:** `numinia.org` serves 688 pages. Most of their addresses come from
> a filename, so every rename silently changes a public URL, and nothing tracks
> which ones changed or whether the old address still resolves.
> **Epistemic:** The filename is a **private** archival decision; the URL is a
> **public** commitment. Today they are the same string.
> **Pragmatic:** `git log` records **192 renames** across the repository's
> history. `astro.config.mjs` declares **9 redirects**.

## The finding

The Oracle, on being told the six phase-B renames would change six published
URLs:

> *"If there is no mechanism, six published URLs die silently today and the one
> in `DEUDA-404` already died in April without anyone noticing. That is not this
> mission's business, but it is debt: the corpus publishes URLs derived from
> filenames and nothing manages their lifecycle."*

The mechanism does exist — `astro.config.mjs` has a `redirects` block, added by
`MIS-066` — but **nothing requires its use, and nothing notices when it is
skipped.**

## Measured

```
688   pages served from web/dist
192   renames in git history (--diff-filter=R, all branches)
  9   redirects declared in astro.config.mjs
```

The 192 is an upper bound: many are files that were never published (`scripts/`,
`.github/`). The point is not the exact ratio but that **no one has ever
compared the two numbers**, because nothing produces them.

### Correction to how this entry was first framed

The `DEUDA-404` case was cited — including by me, in the phase-B config comment
— as *"a URL that died in April and nobody noticed"*. **Reading it properly, it
is not that.** `DEUDA-404` records a page of 890.4 KB that was generated by a
change **discarded before being pushed** (`72bff4c`): the URL never went live,
and the entry is about page weight, not a broken link.

So the strongest evidence for this entry is **weaker than claimed**, and the
claim was mine. What remains is structural rather than anecdotal: 192 renames
against 9 redirects, with nothing measuring the gap. That is enough, and it does
not need a casualty to justify it.

*(The phase-B config comment carries the wrong reading and should be corrected
when this entry is picked up.)*

## Why it is invisible

Same shape as `D-023`, which is why they should be closed together:

| | `D-023` | `D-028` |
|---|---|---|
| Failure | A series never reaches the site | A page moves and its old address dies |
| Signal | none — the build goes green with less to build | none — the build goes green with a different URL |
| Noticed by | counting pages, once, for another reason | nobody yet |

**A build cannot fail for a URL that no longer exists**, because from the
build's point of view nothing is missing — a different file produced a different
page, exactly as instructed.

## What would close it

**1 · A rename that changes a published URL declares its redirect.**
Mechanical, and the data is already there: `git diff --diff-filter=R` names the
old and new paths, and `content.config.ts` says which folders are published.

```js
// scripts/check-url-continuity.mjs
// For each rename in this PR touching a published folder, require a redirect
// in astro.config.mjs from the old URL to the new one — or an explicit
// entry in a `retired-urls` list saying the address is meant to die.
```

**2 · Retirement must be declarable.** Not every old URL deserves to live
forever; what must not happen is a URL disappearing **without anyone deciding
it should**. Same principle as `registration: exempt` (`S-001` §5.0) and the
declared exclusions in `D-023`: a gap and a decision must not look alike.

**3 · A 404 page that says something.** There is no `404.astro`. A reader
hitting a retired address gets the host's default and no way to find where the
document went.

## Closure

Marked RESOLVED when:

- [ ] A guard fails a PR that renames a published file without a redirect or a
      declared retirement
- [ ] `astro.config.mjs`'s redirect list is reconciled against the published
      surface at least once, and the orphans found are recorded rather than
      silently fixed
- [ ] `404.astro` exists and points at `/corpus`
- [ ] The phase-B config comment's misreading of `DEUDA-404` is corrected

The second bullet is the one that carries the entry: **nobody knows today which
published URLs stopped resolving**, and finding out is a measurement no
instrument currently performs.
